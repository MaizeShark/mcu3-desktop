## Summary for next session (additions from session 2, 2026-05-16)

**Touch input:**
- QtCar uses its own `EvDevTouchDriver` looking for `/dev/input/touch` (not Qt's evdev plugin)
- `--touch evdev,autorange` argument needed when launching QtCar
- Virtual touch device created via `make_touch.py` (python-evdev, named `cyttsp6_mt`)
- Click bridge `click_bridge.py` forwards VNC mouse clicks/drags to evdev device
  - Supports `--no-cursor` flag to disable software cursor overlay
  - Must be launched with `DISPLAY=:1 XAUTHORITY=$XAUTHORITY` to avoid reading host display
- `/dev/input` bind-mounted from host into chroot
- `/dev/input/touch` symlinked to the uinput event device

**Startup automation:**
- `~/TeslaMCU/start_all.sh` — full host-side startup script
- `~/TeslaMCU/mcu3/startup.sh` — chroot-side startup script (copy of chroot_start.sh)
- Do NOT bind-mount `/sys` or `/dev` wholesale — breaks host AppArmor
- Safe mounts: `/proc`, `/dev/shm`, `/dev/input`, `/sys/fs/cgroup` (net_cls only)
- DNS fix added to startup: `mkdir -p /var/run/connman && echo "nameserver 8.8.8.8" > /var/run/connman/resolv.conf`
- Cleanup: use `sudo umount -l` for lazy unmount, never `fuser -k` on mcu3/dev
